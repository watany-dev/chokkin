## 判定

v0.7.5 → HEAD の corpus gate にはリリースを止めるデグレードはない。exit criteria はすべて
PASS、gate 6 (CHK003 growth) と gate 7 (`tp` の消失) も PASS。既定 filter の warning 以上は
2,529 → 2,508 件 (-21)、info は 2,847 → 2,863 件 (+16)。

1. **gap による降格は既定 run では 0 件、`--strict` では CHK002 の 135 件。** 既定 run の
   CHANGED 16 件はどれも gap ではない (CHK005 13 件は #808、CHK004 3 件は #861)。gap で
   下がったのは `--strict` の CHK002 error/certain → error/likely だけで、消えた `tp` は 0。
   内訳は下の「gap による降格」。
2. **`--fix` は既定 run では変わらない。`--strict --allow-remove-files --add-missing` では

   (`only Certain-confidence dependency issues are auto-fixable` で skip)、80 件は strict の
   report から消えた finding (#809、#783 / #819)。HEAD にだけ出る計画は 0 件。
3. **diagnostics は 30 → 2,346 件。** 大半は llama_index (1,294) と django (814)。
   llama_index は IPython magic を含む notebook の parse 失敗 (680) と Hatch の partial (608)、

   出るようになったので、この 2 project では text reporter の出力の大半が diagnostics になる。
   ノイズを減らすのは #896 と下のフォローアップ 1 (notebook)。
4. **cold run は transformers -76.8%、llama_index -27.2%、airflow -6.1%。** v0.7.5 の
   フォローアップ 1 (transformers の約 3.8 倍、#771) は解消した。django は +14.4% だが、
   9 回の再測定では +6.9% で範囲が重なる。

v0.7.5 のフォローアップ 2 (CHK005 の fp warning) も解消した。#808 で 13 件が warning/likely →

## フォローアップ候補

1. notebook の IPython magic (`%pip`、`%%time`、`!cmd`) で notebook 全体が parse 失敗になり、
   UnreadModule の gap になる (llama_index 約 670 件、black)。recall (形の認識)。→ 起票
2. `-e` の付かない local path の requirements 行 (`../../../llama-index-core`) が invalid
   requirement として報告される。spec §4 は local path 指定を first-party 候補の opaque 依存と
   しているので、spec と実装のずれ。名前を読めないので何も下げない。recall。→ 起票
3. django tests の相対 import の diagnostics 808 件。→ #896 で追跡
4. django `migrations/*:Migration` の CHK006 info 21 件。→ #926 で追跡
5. CHK002 の stale label 74 件 (v0.7.5 でも同数)。→ #785 の続き

## 実行したコマンド

```sh
S=target/release-validation
git fetch origin --tags
git worktree add "$S/wt-075" v0.7.5
(cd "$S/wt-075" && CARGO_TARGET_DIR="$PWD/../target-075" cargo build --release --locked --bin chokkin)
CARGO_TARGET_DIR="$S/target-head" cargo build --release --locked --bin chokkin
for b in "$S"/target-{075,head}/release/chokkin; do
  echo "$b $("$b" --version) $(md5sum <"$b" | cut -d' ' -f1)"
done

scripts/clone-oss-fixtures.sh
scripts/oss-metrics.py -b "$S/target-075/release/chokkin" -o "$S/metrics/base" -r 1 --with-strict
scripts/oss-metrics.py -b "$S/target-head/release/chokkin" -o "$S/metrics/head" -r 3 \
  --baseline "$S/metrics/base" --with-strict --gate

# --fix の計画 (書き込まない、project ごとに clone を新しくコピーして)
for v in 075 head; do for p in target/oss-clones/*; do
  "$S/target-$v/release/chokkin" <p のコピー> --fix --dry-run --no-cache
  "$S/target-$v/release/chokkin" <p のコピー> --fix --dry-run --no-cache \
    --strict --allow-remove-files --add-missing
done; done   # stderr の `planned` / `skipped` 行を $S/fix/fix-plan.tsv にまとめた

# 実行時間: project ごとに版を交互に (偶数回目は順序を逆に)、7 回ずつ
for i in 1 2 3 4 5 6 7; do for v in 075 head; do
  rm -rf target/oss-clones/<project>/.chokkin
  "$S/target-$v/release/chokkin" target/oss-clones/<project> --reporter json --no-exit-code --no-cache
done; done
```
