## 判定

v0.7.4 → HEAD の corpus gate にはリリースを止めるデグレードはない。exit criteria はすべて
PASS、gate 6 (CHK003 growth) と gate 7 (`tp` の消失) も PASS。既定 filter の warning 以上は
2,850 → 2,615 件 (-235)。減少は FP 修正による消失 (other) と warning → info への降格
(CHANGED) で説明がつき、増えたのは `tp` label の付いた CHK003 / CHK004 だけ。

ただし次の 4 点は記録しておく。1 は v0.7.5 を切る前に判断が要る。

1. **#792 (#776) で mlflow の `--fix` が optional framework を runtime に移すようになる。**
   mlflow が app から library mode に変わり、public な flavor module (`mlflow/tensorflow/`、
   `mlflow/keras/` など) が eager / certain に到達するようになった。その top-level import が
   spec §10 の「top-level import → warning/Certain」に当たり、CHK005 の 9 件が
   warning/likely → warning/certain に上がった (下記 CHANGED)。`--fix` の MoveToRuntime は
   Certain かつ dev 宣言が 1 つの finding に掛かる (`src/fix/plan.rs`) ので、
   `chokkin target/oss-clones/mlflow --fix --dry-run` は v0.7.4 では CHK005 の移動を計画しないが、
   HEAD では次の 9 件を `would move ... to runtime in pyproject.toml` と出す。

   `deepeval`、`haystack-ai`、`keras`、`openai`、`opentelemetry-exporter-otlp-proto-http`、
   `polars`、`psutil`、`ragas`、`tensorflow`

   (`pyspark` は dev 宣言が 2 つで ambiguous として skip、残りは Certain でないので skip)。
   label で `tp` なのは `psutil` だけで、`ragas` / `pyspark` は `fp`。`tensorflow` や `keras` を
   mlflow の runtime 依存に移すのは誤りで、`--fix` を信じたユーザーの manifest を壊す。
   gate は finding の件数と label しか見ないので、この変化は gate に掛からない。
   直し方の候補は「library mode で、public であること以外に到達元のない module の import は
   CHK005 を Likely に留め、`--fix` の対象から外す」(フォローアップ 1、#802)。
2. **#792 で mcp-python-sdk も app → library mode になった** (JSON の `mode`)。CHK006 3 件が
   warning → info に変わるだけで、`--fix` の計画は変わらない。
3. **#790 (#775) で airflow に strict のみの CHK004 が 1 件出る。**
   `task-sdk/tests/task_sdk/execution_time/schema/_mock_version_bundle.py:cadwyn`
   (error/certain)。member ごとの pytest `pythonpath` で task-sdk の test が解決されるように
   なった結果で、`cadwyn` を宣言しているのは airflow-core だけ。test context なので strict にだけ
   出る。spec どおり。
4. **v0.7.4 の #771 (#576) で transformers の実行時間が約 3.8 倍になっている。** v0.7.5 で
   入った遅延ではない (v0.7.4 → HEAD は +1%) が、v0.7.4 の検証は #771 の前の `2691b65` で
   測ったので記録されていなかった。transformers は large で budget の対象外 (下記「実行時間」)。

## フォローアップ候補

1. library mode で CHK005 を Certain にする条件を絞る: public であること以外に到達元のない
   module の top-level import は Likely に留め、`--fix` の MoveToRuntime の対象から外す
   (判定 1、mlflow の `tensorflow` / `keras` ほか)。→ #802
2. #771 の遅延: transformers で約 3.8 倍 (判定 4)。原因箇所は未調査。→ #803
3. airflow の CHK006 fp 10 件と fastmcp の 1 件 (HEAD に残る fp)。→ #787 で追跡
4. CHK002 の stale label 74 件 (v0.7.4 でも同数)。→ #785 の続き
