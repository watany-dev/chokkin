## 判定

(#495) を HEAD で測定し、expectations の 1 項目 (llama_index の CHK001、後述)
を除いて全項目を満たした。その 1 項目は #602 の設計変更によるもので、上限を今回の値に
更新した。更新後の gate は合格する。JSON / baseline の `schema_version` は `"1"` の
まま。CLI flag、exit code、ignore syntax に破壊的変更はない。

### expectations の更新

`scripts/oss-expectations.tsv` の行を今回の値に更新した。範囲外だったのは llama_index
の CHK001 (上限 3+5 に対して 29) だけで、他の行は CHK010 の減少 (#619、#622) と
`reachable_runtime` の実測値を反映しただけ。

llama_index の CHK001 の増加は #602 (`fix(entry): score declared workspace library
members as libraries`) による。commit ごとに測ると `a4f377a` (#601) まで 3 件、
`72cf017` (#602) から 29 件になる。増えた 26 件はすべて integration member
(`llama-index-integrations/.../examples/*.py` など) の到達不能ファイルで、v0.7.0 では
member の wheel target 外のファイルとして `maybe` に留まり既定の filter で隠れていた
ものが、#602 以降は member の public surface に含まれないファイルとして app と同じ
scoring (`likely`) を受ける。R-05 の設計どおりの挙動で、ファイル自体は v0.7.0 でも
到達不能と判定されていた (`--confidence maybe` で表示される)。精度の低下ではないと
判断して上限を 29 に更新したが、`likely` に上げるのが意図と違うなら #602 側を直し、
この行は 3 に戻す。

## 実行コマンド

`oss-metrics.yml` と同じ手順をローカルで実行した。

```bash
make check
cargo build --release --locked --bin chokkin
git worktree add ../chokkin-v070 v0.7.0
cargo build --release --locked --bin chokkin \
  --manifest-path ../chokkin-v070/Cargo.toml --target-dir target/baseline
scripts/clone-oss-fixtures.sh
scripts/oss-metrics.sh -b target/baseline/release/chokkin -o target/oss-metrics-baseline -r 1
scripts/oss-metrics.sh -o target/oss-metrics --gate -r 3
# expectations 更新後の再確認
scripts/oss-metrics.sh -o target/oss-metrics-gate2 --gate -r 1
```

実測詳細は `target/oss-metrics/report.md` を参照する。`target/` は生成物のため、
上表の release 結果を本ファイルに固定する。
