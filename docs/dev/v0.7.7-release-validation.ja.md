## 判定

v0.7.6 → HEAD の corpus gate には、リリースを止めるデグレードはない。exit criteria はすべて
PASS で、gate 6 (CHK003 growth) と gate 7 (`tp` の消失) も PASS。既定 filter の warning 以上は
2,508 → 2,538 件 (+30)、info は 2,863 → 3,070 件 (+207)。増えた分のほとんどは、#962 で読める
ようになった llama_index の notebook に出たもの。

1. **既定 run の CHANGED 18 件に、gap による降格はない。** CHK002 の 17 件は
   warning/certain → warning/likely。どれも PEP 723 script block の dependency で、#984 で
   仕様として `likely` にしたもの。残る 1 件は CHK005 の info/likely → warning/certain
   (llama_index `databricks:openai`)。notebook から到達するようになったため (#962)。
   `--strict` でも消えた `tp` / `fp` は 0。
2. **NEW 296 件 (うち 262 件が info)、GONE 59 件 (info 54 件と、#971 で `graphql` を解決できるようになった CHK010 5 件)。**
   内訳は下の「既定 run の finding diff」。v0.7.6 のフォローアップ 1〜4 と 6・7 (notebook の
   IPython magic、`-e` なしの local path、django tests の相対 import、django `Migration`、`-r` の後ろの
   option、`setup.py` の文字列 requirement) はどれも解消した。
3. **`--fix` の既定 mode で増えた計画は 1 件 (CHK005)。strict-all では、v0.7.6 にしかない計画が
   5 件、HEAD にしかない計画が 34 件。** v0.7.6 にしかない 5 件は mcp-python-sdk の CHK002 の
   削除で、#934 の skipped entry で `likely` になった。HEAD にしかない 34 件は、llama_index の
   notebook から到達した import の CHK003 の追加 33 件と、上の CHK005 1 件。
4. **diagnostics は 2,346 → 924 件。** django 814 → 7 (#896)、llama_index 1,294 → 661 (#962)。
   増えたのは mcp-python-sdk 21 → 43 で、`examples/` 配下の member entry が skipped entry に
   なったため (#934)。
5. **cold run は 8 project すべてで速くなった (-13.0%〜-41.9%)。** llama_index は notebook を
   読むようになった分の仕事が増えても -13.0%。

### `--fix --dry-run` の計画 (§3、clone のコピーに対して)

35 project のそれぞれについて clone を新しくコピーし、両版で次の 2 つを走らせて、stderr の
`planned` / `skipped` 行を比べた。

- `--fix --dry-run --no-cache` (既定)
- `--fix --dry-run --no-cache --strict --allow-remove-files --add-missing` (strict-all)

recall fixture 10 件は含めていないので、v0.7.6 の
レポートの数字 (45 project) とは合わない。

| mode | 版 | planned | うち CHK002 | CHK003 | CHK005 | skipped |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 既定 | v0.7.6 | 14 | 2 | 0 | 12 | 139 |
| 既定 | HEAD | 15 | 2 | 0 | 13 | 138 |
| strict-all | v0.7.6 | 294 | 68 | 214 | 12 | 1,894 |
| strict-all | HEAD | 323 | 63 | 247 | 13 | 1,863 |

- **既定 mode:** HEAD にだけある計画は、llama_index の `planned CHK005 openai` 1 件。上の CHANGED
  CHK005 が `certain` になった分。移動先は dev group に `openai` を宣言している root の
  `pyproject.toml` で、既存の 12 件と同じ扱い。
- **strict-all で v0.7.6 にだけある計画 (5 件):** mcp-python-sdk の CHK002 の削除
  (`datamodel-code-generator`、`mkdocstrings-python`、`pillow`、`pydantic-settings`、
  `strict-no-cover`)。HEAD では `examples/clients/*` の member entry が skipped entry になり
  (#933 / #934)、`not-fixable: only Certain-confidence ...` で skip される。example から使われて
  いるかもしれない dependency は消さない。これは ADR 0005 の意図どおり。
- **strict-all で HEAD にだけある計画 (34 件):** llama_index の CHK003 の追加 33 件
  (`torch`、`boto3`、`pandas` ほか。`docs/examples` の notebook が import しているもので、root の
  `pyproject.toml` に追加する) と、上の CHK005 1 件。
- **skipped の差:** django -2 と llama_index -34 は、strict で GONE になった CHK001 の分。
  mcp-python-sdk +5 は上の CHK002。

## 実行時間 (§4、ms、cold、wall clock)

v0.7.6 と HEAD を交互に 7 回ずつ走らせた。毎回 `.chokkin` を消し、`--reporter json --no-exit-code --no-cache`
で、偶数回目は順序を逆にした。値は中央値 (最小〜最大)。v0.7.6 のレポートとはマシンが違うので、
絶対値ではなく版どうしの差を見る。

| Project | v0.7.6 | HEAD | 差 |
| --- | ---: | ---: | ---: |
| airflow | 2,868 (2,749〜2,972) | 1,665 (1,638〜1,862) | -41.9% |
| llama_index | 1,537 (1,461〜1,595) | 1,337 (1,287〜1,392) | -13.0% |
| transformers | 1,496 (1,434〜1,577) | 1,075 (1,044〜1,118) | -28.1% |
| mlflow | 785 (764〜833) | 584 (565〜625) | -25.6% |
| django | 532 (477〜560) | 417 (401〜456) | -21.6% |

| sqlalchemy | 388 (357〜433) | 261 (253〜281) | -32.7% |

- どの project でも範囲が重ならない。主因は #944〜#948 (module 解決、symbol 解析、dependency /

## フォローアップ候補

1. CHK002 の stale label 74 件 (v0.7.6 でも同数)。→ #785 の続き
2. workspace member の CHK005 で、dev 宣言が root にあるとき、`--fix` の移動先が root の
   `pyproject.toml` になる (llama_index の 13 件)。v0.7.6 から変わらない挙動。member の runtime に
   追加するほうが意図に合う可能性がある。要確認
3. llama_index `docs/examples` の notebook の import が CHK010 info 240 件になる。info なので
   既定の出力には出ない。notebook を docs として扱う設定 (`exclude` など) を案内するかどうか
4. `code cell not read` の残り約 45 件 (`%run`、`%%writefile`、cell の途中の cell magic、
   syntax error)。cell 単位で落とすのは #962 の仕様どおり

## 実行したコマンド

```sh
S=target/release-validation
git fetch origin --tags
git worktree add "$S/wt-0.7.6" v0.7.6
(cd "$S/wt-0.7.6" && CARGO_TARGET_DIR="$PWD/../target-076" cargo build --release --locked --bin chokkin)
CARGO_TARGET_DIR="$S/target-head" cargo build --release --locked --bin chokkin
for b in "$S"/target-{076,head}/release/chokkin; do
  echo "$b $("$b" --version) $(md5sum <"$b" | cut -d' ' -f1)"
done

scripts/clone-oss-fixtures.sh
scripts/oss-metrics.py -b "$S/target-076/release/chokkin" -o "$S/metrics/base" -r 1 --with-strict
scripts/oss-metrics.py -b "$S/target-head/release/chokkin" -o "$S/metrics/head" -r 3 \
  --baseline "$S/metrics/base" --with-strict --gate

# --fix の計画 (書き込まない。project ごとに clone を新しくコピーして)
for v in 076 head; do for p in target/oss-clones/*/; do
  "$S/target-$v/release/chokkin" <p のコピー> --fix --dry-run --no-cache
  "$S/target-$v/release/chokkin" <p のコピー> --fix --dry-run --no-cache \
    --strict --allow-remove-files --add-missing
done; done   # stderr を $S/fix/<project>.<v>.<mode>.err に取り、`planned` / `skipped` 行を比べた

# 実行時間: project ごとに版を交互に (偶数回目は順序を逆に)、7 回ずつ
for i in 1 2 3 4 5 6 7; do for v in 076 head; do
  rm -rf target/oss-clones/<project>/.chokkin
  "$S/target-$v/release/chokkin" target/oss-clones/<project> --reporter json --no-exit-code --no-cache
done; done
```
